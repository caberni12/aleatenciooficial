USO: INGRESAR CREDENCIALES Y CONECTAR
- PRUEBA comienza con RUT 1-9, editable.
- Escribir Usuario REST y Clave REST entregados por el proveedor.
- Pulsar Guardar y conectar en la tarjeta del ambiente elegido.
- El sistema guarda las credenciales cifradas, valida el login y activa
  Facturacion.cl en ese ambiente. PRUEBA corresponde a CERTIFICACION.
- Un login rechazado no activa otro proveedor ni cambia el ambiente.
- El RUT queda visible y editable. Usuario y clave se limpian al guardar.
  Para reemplazarlos, volver a ingresar los tres datos.
- PRODUCCION tiene su propio RUT, usuario y clave. Al conectar esa tarjeta,
  el ambiente activo cambia a PRODUCCION. Usar las credenciales REST
  productivas que entregue Facturacion.cl.
- Probar login verifica las credenciales guardadas; no cambia el proveedor
  ni el ambiente. No guardar contraseñas en config.js.

El guardado usa Supabase Vault y no requiere ALE_MANAGEMENT_TOKEN.
Las credenciales históricas en Secrets son una alternativa mientras no
exista un registro en Vault. Eliminar desde cPanel deshabilita ese ambiente,
incluidas las alternativas anteriores. La clave no se devuelve al cPanel.

EMISION Y CONSULTAS
- Factura 33/34, boleta 39/41, guía 52 y notas 56/61.
- Los datos del receptor corregidos se envían al proveedor y se guardan en
  Clientes cuando corresponde.
- El RUT 1-9 sirve para el acceso del emisor DEMO. El RUT del receptor debe
  tener número entre 10000 y 99999999 y dígito verificador válido; se comprueba
  antes de enviar al proveedor.
- Las guías requieren patente y RUT del transportista.
- Las notas requieren tipo, folio y fecha del documento de referencia.
  Corrección de monto requiere monto explícito; corrección de texto lleva
  monto cero. Para anulación se toma el total actual del pedido: revisar
  su coincidencia con el original si el pedido cambió después de emitir.
- Historial con ambiente, PDF, copia cedible cuando corresponda y XML enviado.
- Datos ticket descarga Head, Foot y TED en JSON para el componente impresor.
  Requiere módulo de ticket contratado en Facturacion.cl e impresor compatible.
  Este paquete no instala un controlador de impresión.
- El XML descargable es el enviado a integración, no el XML firmado SII.

SI UNA EMISION QUEDA PENDIENTE
Un corte puede ocurrir después de que el proveedor reciba el documento.
El sistema conserva INDETERMINADO y bloquea el reenvío automático.
Revisar el documento en Facturacion.cl y usar Revisar emisión en el historial.
Indicar el folio confirmado y marcar la confirmación. El sistema consulta
su PDF y registra el resultado sin enviar una nueva emisión.
Si el proveedor confirma que no emitió, un administrador debe resolver el
registro antes de intentar nuevamente; no cambiar el estado a ciegas.
